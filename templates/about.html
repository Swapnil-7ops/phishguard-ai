PBL Project Overview
Explainable Security & Problem Statement
BE Information Technology

PhishGuard AI is an Explainable Multi-Modal Phishing Detection System designed for Academic Programming-Based Learning (PBL). Phishing remains the primary attack vector for credential theft, ransomware initiation, and corporate compromise. Traditional signature-based blacklists suffer from zero-hour latency, while opaque deep learning classifiers fail to offer explainable rationale for security operations center (SOC) analysts.

This project addresses these shortcomings by separating statistical ML inference (Random Forest), deterministic rule indicators, NLP linguistic analysis, and explainable risk scoring into an integrated, transparent architecture.

High-Level Architecture Pipeline
Input [URL / Message / QR / Screenshot]
  ├── URL Flow: Normalize ➔ 25-Feature Extraction ➔ RandomForest Model (60% wt) + Rule Engine (40% wt) ➔ Risk Score (0-100)
  ├── Message Flow: NLP Heuristics + TF-IDF Logistic Regression ➔ Link Extraction ➔ Cascaded URL Analysis ➔ Combined Risk
  ├── QR Code Flow: Decoded via pyzbar ➔ Extracted URL dispatched into URL Analyzer (No Automatic Navigation)
  └── Multimodal Vision: Visual inspection for brand spoofing / fake login dialogs
        └── Output ➔ Transparent Explainability Breakdown ➔ MongoDB Persistent Audit Log
Component Breakdown
1. ml/feature_extractor.py

What: Extracts 25 lexical and structural numerical features.
Why: ML models require structured inputs. These metrics reflect deliberate adversarial engineering without visiting malicious web servers (SSRF safe).
Input/Output: Receives raw URL string; returns dict of 25 float/int features.

2. ml/train_url_model.py & RandomForestClassifier

What: Trains an ensemble of 100 decision trees on offline holdout sets.
Why: Random Forest handles feature correlation, non-linear boundaries, and prevents overfitting through bagging and feature subsampling.
Output: Persisted model artifact models/url_model.pkl and verifiable holdout confusion matrix.

3. services/rule_engine.py

What: Evaluates explicit cybersecurity indicators (e.g. IP host, @ redirect, disposable TLD).
Why: Statistical models can fail on novel structural tricks. Heuristic rules guarantee deterministic detection of critical red flags.

4. services/risk_engine.py

What: Blends ML probability (up to 60 pts) and Rule points (up to 40 pts) into a 0–100 Risk Score.
Key principle: Model Confidence (posterior probability) is distinct from Risk Score (composite security index).

5. services/message_analyzer.py

What: Scans messages for urgency, threats, and OTP interception, extracts URLs, and cascades them into the URL Analyzer.

6. database/mongodb.py

What: Manages scan history in MongoDB with automatic transparent in-memory fallback if mongod is not active.

Documented Real-World Limitations
  • No Live Network Crawling: The system analyzes lexical patterns without downloading HTML payloads. This prevents SSRF and malware execution on the host server.
  • Adversarial Evasion: Attackers can register aged domains and configure reverse proxies (e.g. Modlishka, Evilginx) that exhibit clean lexical features.
  • HTTPS Prevalence: Over 85% of modern phishing websites utilize valid TLS/SSL certificates via Let's Encrypt, making HTTPS usage an insufficient signal of legitimacy.
  • Volatile URL Shorteners: Without actively following HTTP redirects, short links hide destination features.
  • Decision-Support Tool: The system produces risk indicators to aid analyst judgment; it is not absolute mathematical proof of maliciousness.
